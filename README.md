# AU Youth Engagement & Skills Platform

A full-stack web app for African Union youth interns, volunteers, and fellows:
an announcement feed, a searchable skill directory, a help-request board that
matches people to skills, and a tiered admin panel.

## Stack

- **Framework:** Next.js 16 (App Router, TypeScript, Server Actions)
- **Styling:** Tailwind CSS v4, self-hosted fonts (Fraunces, Inter, IBM Plex Mono via `@fontsource`)
- **Database:** Postgres via **Drizzle ORM** (`drizzle-orm/node-postgres` + `pg`) — built and tested against [Neon](https://neon.tech)
- **Auth:** Custom cookie-based sessions (HttpOnly JWT via `jose`) + `bcryptjs`
  password hashing. Role-based access enforced server-side in every Server
  Action and page (not just hidden UI).
- **Charts:** recharts (admin analytics)
- **Icons:** lucide-react
- **Tests:** Vitest

## Local development

```bash
npm install
cp .env.example .env.local   # then fill in DATABASE_URL and SESSION_SECRET
npx drizzle-kit push          # applies the schema to your Postgres database
npx tsx src/db/seed.ts        # seeds departments, skills, and demo users
npm run dev                    # http://localhost:3000
npm test                        # runs the Vitest suite
```

For local development without Neon, any local Postgres works — e.g.
`DATABASE_URL=postgresql://postgres:postgres@localhost:5432/au_youth?sslmode=disable`.

## Deploying: Render + Neon

### 1. Create the Neon database

1. [neon.tech](https://neon.tech) → new project.
2. Dashboard → **Connect** → copy the **pooled connection string** (has
   `-pooler` in the hostname). Pooled is recommended — Neon's direct
   connections have a low concurrent-connection limit that a normal running
   Node server can exhaust under load; the pooler (PgBouncer) handles that.
3. It looks like:
   `postgresql://user:password@ep-xxxx-pooler.region.aws.neon.tech/neondb?sslmode=require`

### 2. Push the schema to Neon

From your machine, with that connection string:

```bash
DATABASE_URL="<your neon pooled connection string>" npx drizzle-kit push
DATABASE_URL="<your neon pooled connection string>" npx tsx src/db/seed.ts
```

(Seeding is optional — skip it for a real deployment and just create your
Super Admin account by signing up, then promoting it — see "First deploy"
below.)

### 3. Deploy to Render

**Using the included `render.yaml` blueprint (recommended):**
1. Push this repo to GitHub (see below).
2. Render dashboard → New → Blueprint → point it at your repo. It reads
   `render.yaml` and creates the service.
3. Set `DATABASE_URL` in the Render dashboard (marked `sync: false` in the
   blueprint, so it won't be committed to git) to your Neon pooled connection
   string.
4. `SESSION_SECRET` is auto-generated by the blueprint.

**Manually, without the blueprint:**
1. Render dashboard → New → Web Service → connect your repo.
2. Runtime: Node. Build command: `npm install && npm run build`. Start
   command: `npm start`.
3. Environment → add `DATABASE_URL` (your Neon string) and `SESSION_SECRET`
   (any long random string — `openssl rand -hex 32`).

### File uploads on Render

Profile photos and post attachments are written to disk (`UPLOAD_DIR`, see
`.env.example`). Render's filesystem is **ephemeral on the Free plan** —
uploaded files vanish on redeploy or restart. Two options:

- **Do nothing.** Uploads still work fine between deploys, just not across
  them. Fine for testing.
- **Add a Render persistent disk** (requires a paid plan): Render dashboard →
  your service → Disks → add one, mount it at `/var/data/uploads`, and set
  `UPLOAD_DIR=/var/data/uploads`. The `render.yaml` blueprint already does
  this — delete that block if you're on the Free plan.

For a fully durable, host-agnostic setup, swap `src/lib/upload.ts` for a real
Supabase Storage / Cloudflare R2 upload — call sites only need the returned
URL string, nothing else changes.

### First deploy: creating your Super Admin

There's no seeded account on a real deployment unless you ran the seed step
above. Instead:
1. Sign up normally through `/signup` — you'll land as a regular Member.
2. Connect to your Neon database (Neon's SQL Editor, or `psql`) and run:
   ```sql
   UPDATE users SET system_role = 'SUPER_ADMIN', is_poster = true WHERE email = 'you@example.com';
   ```
3. Log out and back in (or just refresh) — you now have Super Admin access
   and can create departments and promote other admins from `/admin`.

## What's implemented

### Core
- **Public landing page** with a live network diagram, stats, and recent updates
- **Open self-signup** (no approval step) capturing name, email, phone, department,
  program type, title, bio, skills (free-tag input), and social links
- **Announcement feed** — platform-wide or department-scoped, pinned items float
  to the top, image/PDF attachments, edit/delete for the author or a dept admin
- **Skill directory** — live search across name/title/skills, filters by
  department and program type, avatars, pagination, contact info hidden from
  logged-out visitors
- **Help request board** — post a request tagged with required skill(s); any
  member with a matching skill is notified automatically; requests can be
  claimed ("I can help"), stepped back from / reopened, resolved, and — for
  the requester or a dept admin — edited or deleted
- **Member dashboard** — profile summary + photo, skill list, requests
  submitted vs. helped with, email-verification banner
- **Admin panel**
  - `/admin` — role-scoped analytics with charts (members per department,
    open/resolved help requests, most-listed skills), recent audit log
  - `/admin/departments` — Super Admin creates departments and assigns a
    Dept Admin from that department's existing members
  - `/admin/users` — searchable, paginated member list; Super Admin sees
    everyone, Dept Admin sees their own department; grant/revoke posting
    privilege, deactivate/reactivate accounts; a Dept Admin can also hand
    their role directly to another member without going through Super Admin
  - `/admin/audit` — full, filterable/searchable audit log of every admin
    action (who, what, when)
  - `/admin/outbox` — see "Email" below

### Account safety
- **Rate limiting** on signup (per IP) and login (per IP and per email),
  DB-backed fixed-window limiter (swap for Redis/Upstash for multi-instance deployments)
- **Email verification** — a banner on the dashboard lets an unverified
  member resend the link
- **Password reset** — `/forgot-password` → emailed link → `/reset-password`,
  with an enumeration-safe response ("if an account exists...") and a 30-minute
  token expiry

### Notifications
- **In-app notification bell** in the nav — unread count, mark-read,
  mark-all-read — fed by help-claimed, help-reopened, help-resolved, and
  skill-match events
- **Email** — no real provider (Resend/SendGrid) is configured.
  `src/lib/mailer.ts` writes every "sent" email to a `dev_emails` table
  instead, viewable at `/admin/outbox` (Super Admin only), so verification
  and password-reset links are fully clickable and testable end-to-end. Swap
  the body of `sendEmail()` for a real provider call in production — call
  sites don't change.

### File uploads
- Profile photos and post attachments (image or PDF, 5MB limit), served
  through `/uploads/[filename]`. See "File uploads on Render" above for the
  persistence caveat and how to fix it.

### Polish
- Loading skeletons on data-heavy routes (directory, announcements, help
  requests, admin users)
- Pagination on the directory and the admin users table

## Project structure

```
src/
  db/
    schema.ts       # Drizzle schema (Postgres / pg-core)
    index.ts         # DB client singleton (node-postgres pool)
    seed.ts          # demo data
  lib/
    auth.ts          # session cookies, password hashing, re-exports permissions
    permissions.ts    # pure role-check functions (unit tested)
    rate-limit.ts      # DB-backed rate limiter
    mailer.ts           # dev email outbox stand-in
    upload.ts            # configurable-directory file upload stand-in
    format.ts             # shared date formatting helpers
    actions/                # Server Actions: auth, posts, help-requests, profile, admin, notifications
    __tests__/                # Vitest unit tests
  app/
    (auth)/login, signup, forgot-password, reset-password
    verify/
    uploads/[filename]/route.ts  # serves uploaded files from UPLOAD_DIR
    announcements/
    directory/
    help-requests/
    dashboard/, dashboard/profile/
    admin/, admin/users/, admin/departments/, admin/audit/, admin/outbox/
  components/
    Nav.tsx, NotificationBell.tsx, VerifyBanner.tsx, Skeleton.tsx
render.yaml           # Render blueprint (web service + optional persistent disk)
```
